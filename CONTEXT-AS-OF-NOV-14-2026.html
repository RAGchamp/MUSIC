2. Tokens and the Context Window

What is a token?

Claude doesn't read letters or whole words. It reads tokens, chunks of text that are usually part of a word. As a rough rule for English, 1 token ≈ 4 characters ≈ ¾ of a word. Code, numbers, symbols and non-English text usually take more tokens per character. Some examples:

TextRoughly
"Play the original recording"≈ 5 tokens
One page of plain English (~500 words)≈ 650 tokens
The Music Practice App's index.html (39 KB)≈ 10–12k tokens
One screenshot attached to a message≈ 1–2k tokens
What is the context window?

It is everything Claude can see at once while it writes its next reply: its instructions, the tool descriptions, and the whole conversation so far, including every file it read and every command output. Claude has no other memory of the session. If something isn't in the window, Claude doesn't know it. This session's window is 1 million tokens (written 1m), enough for roughly 750,000 words.

4. Box: System Prompt (3.1k tokens)

The system prompt is the standing instructions Claude Code gives the model before the conversation starts. You never see it in the chat, but it is sent with every single request. At 3.1k tokens (about 2,300 words) it is small. It contains:

PartWhat it tells Claude
Who it isThat it is Claude Code, Anthropic's command-line coding agent, working with you on your goals.
How the harness worksReplies are shown as Markdown in the terminal; tools run under the permission mode you chose; a denied tool call means you said no.
Ground rulesConfirm before actions that are hard to undo or that publish something (that's why every git push in this project waited for your "yes push it"); report results honestly; keep your personal details private.
MemoryWhere the long-term memory folder is and how to write memory files.
EnvironmentWorking folder C:\Daya\RAGchamp\BLOG, Windows 11, the PowerShell and Git Bash shells, today's date (2026-11-14), the model name, and the scratchpad folder for temporary files.
Context managementThat old parts of a long conversation are summarized automatically, so Claude doesn't need to rush or hand off work early (see section 11).

5. Box: System Tools (23.6k tokens)

Claude can't touch your computer directly. It asks Claude Code to run a tool. Each tool comes with a written description and a JSON "schema" listing its inputs, and all of that sits in the context so Claude knows what it can do. "Deferred" tools: listed, but not counted

The full /context table also listed System tools (deferred): 26.3k. Those tools aren't in the grid. Only their names are in the context, e.g. WebFetch, WebSearch, Monitor, NotebookEdit, CronCreate, EnterPlanMode, EnterWorktree, SendMessage, ArtifactComments, ArtifactData and others. If Claude needs one, it calls ToolSearch to load its full description, and only then does it cost tokens. The 26.3k is what it would cost to load them all. Keeping them deferred saves about 26k tokens on every request. 6. Box: MCP Server Instructions (717 tokens)

MCP (Model Context Protocol) is the standard way to plug extra tools into Claude: connectors to services such as Google Drive or Slack. An MCP server can send a short set of instructions on how to use its tools, and those count here.

This session had one connector: claude.ai Claude Docs, which creates and edits living documents on claude.ai. Its 717 tokens of instructions explain when to make a doc, how to start one with a skeleton of sections, and how to answer comments left on a doc. It gets one green square only because the grid rounds up; the real size is about a seventh of a square.

Its tools are separate: the table lists MCP tools (deferred): 2.2k for its 8 tools (batch, guide, update, create, read, query, export, delete). Like the deferred system tools, they are only fully loaded when needed. None were used for the Music app.

7. Box: Skills (6k tokens)

A skill is a packaged set of instructions for one kind of task (making a Word file, reviewing code, drawing charts…). To keep the context small, Claude Code puts only each skill's name and one-paragraph description in the context. That's enough for Claude to know a skill exists and when to use it. The skill's full instructions are loaded only when it is invoked, and they then count as Messages. About 30 skills were listed, for 6k tokens in total:

8. Box: Messages (148.1k tokens)

Messages is the conversation itself, and it is the only box that keeps growing. It includes much more than the text you typed:

  • Your messages, including the screenshots you pasted (Images #9 to #13: the Scan-folder button, the side lines, the Sound dropdown, the fretboard and the /context screen).
  • Claude's replies, including its reasoning before each reply.
  • Every tool call and its result: every file read, every file written (the full text of a Write is part of the conversation), every command and its output, every screenshot Claude looked at.
  • The summary of the earlier conversation. This session had already been compacted once (see below), so it starts with a summary of all the earlier BLOG work.
  • Small system notes, such as "this file changed on disk" or "the user hasn't heard from you in a while".

9. Box: Free Space (785.6k tokens)

Free space is room the conversation can still grow into: 1,000k − 181.4k used − 33k reserved = 785.6k (78.6%).

That's plenty: the session could keep going for a long time (more than four times what it has used so far) before anything is compacted. Free space is not "wasted". Claude doesn't get slower or less careful because the window is mostly empty, but an emptier window is cheaper and faster per request.

10. Box: Autocompact Buffer (33k tokens)

The crossed-out squares at the end of the grid are a reserve that the conversation is not allowed to fill. It is 33k tokens, 3.3% of the window. It exists for two reasons:

  1. It is the trigger line. When Messages grow until they would run into the buffer, at about 1,000k − 33k = 967k tokens in use, Claude Code starts auto-compaction (next section).
  2. It leaves room to do the compaction. Summarizing the conversation is itself a model request that needs space for its output, the summary. The buffer makes sure that space exists, so the session never hits a hard "context is full" error in the middle of a task.

You can't use those 33k tokens for conversation, but they keep long sessions running smoothly.

11. The Auto-compact Window (1m) and Compaction

The last line of the screen, "Auto-compact window: 1m tokens", is the window size that auto-compaction is measured against. Here it equals the full 1-million-token window of Opus 5.5 in this session. All the percentages and the 33k buffer are worked out from it.

What happens when it fills up
Step 1 · The conversation grows

Every message, file read and command output is added to Messages, and free space shrinks.

Step 2 · It reaches the buffer (≈967k in use)

Claude Code sees that the next turns might not fit, and starts compaction automatically. You don't have to do anything.

Step 3 · The old part is summarized

The older conversation is replaced by a written summary: what you asked for, the decisions made, which files were changed and how, errors and fixes, what's still pending, and the exact next step. The most recent messages may be kept word for word. The full original conversation is still saved on disk as a transcript (.jsonl), so details can be looked up again if needed.

Step 4 · Work continues

The session goes on with the summary in place of the old messages. Messages drop to a small size and free space opens up again.

This session has already been compacted once. It began as the BLOG session (the AI article, MUSIC-BASICS.html, the audio analysis…). When that ran out of room, it continued "from a previous conversation that ran out of context", with a summary at the top. The Music app was built after that, so the 148.1k of Messages includes that summary plus all the Music-app work.
You can also do it yourself
Claude Code commands
/context            show this map of the context window
/compact            summarize the conversation now
/compact keep the song-library format and the git rules
                    summarize, telling it what to keep in detail
/clear              start a completely fresh conversation (nothing kept)
Watch out
  • A summary is shorter than the original. Exact wording, long code listings and small details can be lost. That's why important, lasting facts belong in a CLAUDE.md file (see section 12), not only in the chat.
  • Compacting takes a moment, and during it Claude isn't working on your task.

13. Tips: Keeping the Context Healthy

  1. Start Music-app sessions in C:\Daya\RAGchamp\MUSIC. CLAUDE.md is then loaded automatically, and the BLOG history doesn't take up room.
  2. Use /clear between unrelated jobs, e.g. after finishing the Music app and before starting on something unrelated. A fresh session starts at ~33k (prompt + tools + skills) instead of carrying 148k of old messages.
  3. Point Claude at exact files and lines. "Change the Play button in index.html" costs less than "look through everything".
  4. Keep screenshots focused. A crop of the part that matters (like the Scan-folder button or the Sound dropdown you shared) is cheaper and clearer than a full-screen capture.
  5. Put lasting rules in CLAUDE.md, not just in chat, so they survive compaction and new sessions.
  6. Run /context now and then on long jobs to see how full the window is.

14. Glossary

TermMeaning
TokenThe unit Claude reads and writes in: about 4 characters or ¾ of an English word.
Context windowEverything Claude can see at once when it writes a reply. Here: 1,000,000 tokens.
k / mThousand / million tokens (181.4k = 181,400; 1m = 1,000,000).
System promptClaude Code's standing instructions to the model, sent with every request.
Tool / schemaAn action Claude can ask Claude Code to perform (read a file, run a command), and the JSON description of its inputs.
Deferred toolA tool listed by name only. Its full description is loaded with ToolSearch when needed.
MCPModel Context Protocol: the standard for connecting outside tools and services (connectors) to Claude.
SkillA packaged set of instructions for one kind of task. Only its description is loaded until it is used.
MessagesThe conversation: your messages, Claude's replies, and all tool calls and results.
CompactionReplacing older conversation with a summary to free up room.
Autocompact bufferThe reserved 33k at the end of the window. Reaching it triggers compaction, and it leaves room to write the summary.
Auto-compact windowThe window size compaction is measured against (1m here).
CLAUDE.mdA project memory file that Claude Code loads at the start of every session in that folder.
Transcript (.jsonl)The full record of a session saved on disk; it is kept even after compaction.
